01 · Executive Overview

Zero-Copy Cross-Cloud Conversational Analytics

Cross-Cloud Conversational Analytics turns Google Cloud into a unified AI reasoning control plane across hybrid data estates—allowing business users, support specialists, and risk analysts to ask natural-language questions spanning live AWS operational databases and 66M-row BigQuery warehouses without upfront cross-cloud ETL movement.

CAPABILITY VALUE · 01

Eliminates the “Migration Tax” on AI Adoption

Over 80% of enterprise AI adopters operate multi-cloud topologies where core ledgers or CRM databases reside on AWS while analytics and ML live in BigQuery. Querying operational records in-place compresses Time-to-Value from 9-month ETL migrations down to days.

CAPABILITY VALUE · 02

Real-Time HTAP Signal Fusion

Batch warehouse replication lags by minutes to hours. The Analytics Agent fuses sub-minute AWS banking balances and open support tickets with historical BigQuery ML inferences (churn_risk_score, fraud_risk_score) in a single conversational turn.

CAPABILITY VALUE · 03

Data Sovereignty & Minimal Egress Footprint

Regulated financial and healthcare tables remain inside their designated cloud enclaves. Instead of bulk-replicating terabytes of raw operational storage across clouds, only kilobytes of filtered entity rows or aggregated answers traverse the wire.

CAPABILITY VALUE · 04

“Win the Brain, Guide the Gravity” Control Plane

Establishes Gemini Enterprise and Vertex AI Agent Engine as the daily decision layer first. Query telemetry then identifies high-frequency cross-cloud joins that justify targeted BigQuery Omni federation or Datastream CDC replication later.

ARCHITECTURAL SCOPE CLARIFICATION Single-Cloud GCP Native vs. Hybrid Multi-Cloud Execution

When 100% of data already resides in Google Cloud (BigQuery, Cloud SQL, AlloyDB, Spanner), custom MCP wrappers are unnecessary—deployments connect directly to Google’s first-party Conversational Analytics API (geminidataanalytics.googleapis.com) and Managed BigQuery MCP (bigquery.googleapis.com/mcp).

When enterprise data spans AWS + Google Cloud (as deployed in ani-labs), Cross-Cloud Conversational Analytics bridges the divide via governed Model Context Protocol (MCP) endpoints and BigQuery cross-cloud federation—delivering one conversational interface across clouds.

06 · Trust, Security & Operational Guardrails

Enterprise CISO, Production DBA & FinOps Controls

Connecting conversational AI to operational banking and CRM data requires defense-in-depth across identity, SQL synthesis, workload isolation, and cloud spend.

Identity & Access

End-User OIDC & Row-Level Security

Eliminates “Confused Deputy” shared credentials by requiring Cloud Run IAM + MCP Toolbox authRequired OIDC tokens, propagating caller identity into BigQuery Row Access Policies (SESSION_USER()) and Postgres session claims.

Control: Per-User RBAC + Audit Attribution
Prompt-Injection Defense

Parameterized SQL + Model Armor

Free-text columns like support_tickets.issue carry Indirect Prompt Injection risk. Binding typed parameters in MCP Toolbox ($1) eliminates arbitrary SQL stacking, reinforced by Google Cloud Model Armor screening.

Control: Zero Raw SQL Concatenation
DBA Workload Safety

Read Replicas & 5s Statement Caps

Protects primary AWS OLTP transactions during peak traffic by routing exclusively to dedicated Read Replicas over HA VPN, enforcing bounded connection pools, default_transaction_read_only = on, and statement_timeout = '5s'.

Control: Zero Primary CPU Contention
FinOps Cost Governance

Dry-Run Pre-Checks & Byte Circuit Breakers

Prevents runaway scans across multi-gigabyte event tables (ccca.app_events) via mandatory partition filters, BigQuery dry_run=True validation, and hard maximum_bytes_billed per-query caps.

Control: Predictable Cost / 1,000 Prompts
Metric Consistency

Looker & Conversational Analytics Semantics

Prevents two executives from getting different definitions of “Active Deposit Balance” or “High Churn” by anchoring analytical queries on governed LookML measures and BigQuery semantic views.

Control: Governed Single Source of Truth
Context Hygiene

Truncation Metadata & PII Masking

Replaces silent row caps with explicit has_more + total_count_estimate headers (prompting SQL aggregation instead of partial sampling) and enforces column-level PII masking on sensitive customer identifiers.

Control: Zero Silent Sampling Drift

def _query_postgres(sql: str):
    conn = psycopg2.connect(
        host=os.environ.get("POSTGRES_HOST"),
        database=os.environ.get("POSTGRES_DB"),
        user=os.environ.get("POSTGRES_USER"),
        password=os.environ.get("POSTGRES_PASSWORD"),
    )
    cur = conn.cursor(cursor_factory=RealDictCursor)
    cur.execute(sql)

Slide 05 / 10 · Solving Context-Window Physics Bifurcated Routing Architecture

Scaling Past LIMIT 5: Bifurcated Query Architecture

Joining millions of rows inside an LLM’s token window either truncates accuracy (LIMIT 5) or overflows context. Enterprise scale bifurcates routing by cardinality:

Fast Path A: Entity Triage (1–50 Keys)

Engine: MCP Toolbox for Databases (genai-toolbox) over HA VPN to AWS Read Replicas.
Result: Pooled connections, parameterized ANY($1) lookups, OIDC per-user auth, <1.5s tool execution.

Analytical Path B: Population OLAP (100 – 50M+ Rows)

Engine: Managed BigQuery MCP + Conversational Analytics API + BigQuery EXTERNAL_QUERY & BigQuery Omni.
Result: Distributed SQL joins run in BigQuery slots; only compact summary rows enter Gemini’s context.

Design Principle: Use Gemini to plan queries and synthesize insights—use BigQuery Dremel & Omni slots to execute relational joins.

Slide 09 / 10 · Architectural Discipline Fit vs. Anti-Patterns

Clear Guardrails: Choosing the Right Cross-Cloud Tool

Credible enterprise architecture pairs bold capabilities with crisp boundaries on when another Google Cloud primitive is superior:

Use Live MCP Toolbox When…

Sub-minute operational freshness matters and queries target specific entities or small cohorts (1–50 keys) on indexed AWS Read Replicas.

Use BigQuery Omni When…

Analytical queries scan large AWS S3 / Iceberg / Delta tables where local AWS compute eliminates cross-cloud egress fees.

Use Datastream CDC When…

High-concurrency BI dashboards run the same cross-cloud join 500+ times/day—continuous serverless CDC into BigQuery is 10x cheaper and 20x faster.

Disqualification Rule: Do not pitch cross-cloud MCP querying to 100% AWS-only estates with zero Google Cloud data or AI anchor.
