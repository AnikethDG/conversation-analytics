03 · Enterprise Architecture & Governance

      
How It Scales to 50M+ Rows Without Risking Production DBs

      

        We never stream millions of rows into an LLM context window. The agent routes operational lookups and warehouse cohort joins down two purpose-built Google Cloud paths.
      


      

        

          
PATH A · OPERATIONAL LOOKUPS (<50 KEYS)

          
Google MCP Toolbox → AWS Read Replicas

          
Handles customer-360 triage, live account status, and P1 ticket checks in milliseconds without touching primary OLTP writers.

          
    
            
  • Declarative tools.yaml with built-in connection pooling and parameterized SQL.
    • 
            
  • Batches multi-entity keys via WHERE email IN (...) to prevent N+1 query storms.
    • 
          

        


        

          
PATH B · WAREHOUSE ANALYTICS (50M+ ROWS)

          
Managed BigQuery MCP + Federation / Omni

          
Executes massive cohort scans inside BigQuery compute slots and returns only compact summary rows (<2 KB) to Gemini.

          
    
            
  • Queries argolis.ccca (50M risk profiles + 16M events) with partition pruning.
    • 
            
  • Uses BigQuery EXTERNAL_QUERY or BigQuery Omni (S3 Iceberg) for large cross-cloud joins.
    • 
          

        

      


      

        

          Per-User OIDC & RLS
          Propagates analyst identity to BigQuery SESSION_USER() row-level security.
        

        

          Zero Static Keys
          SPIFFE AGENT_IDENTITY mTLS + Cloud Run IAM authentication.
        

        

          OLTP Circuit Breakers
          Dedicated AWS Read Replicas with strict 5,000 ms statement timeouts.
        

        

          FinOps Cost Caps
          Pre-execution BigQuery dry_run validation + 10 GB scan budget.
